# Audit complet du site jameslaplume.ca — 31 octobre 2026

Audit réalisé sur le site en ligne (https://jameslaplume.ca) et sur le dépôt
`JamesLaplume123/JamesLaplume123.github.io`, avant la refonte complète.

## Résumé exécutif

Le fond est bon : le message est clair, les textes sont soignés, les images
conceptuelles sont de grande qualité et les trois documents de référence
(`docs/`) définissent une architecture et un système visuel cohérents.
Le problème est l'exécution : trois générations de code empilées (v1, v3, v4
plus une couche « signature »), des bugs d'affichage visibles par tous les
visiteurs, et un dépôt encombré de fichiers morts. Le site mérite une
reconstruction propre sur une seule fondation — c'est ce que cette refonte fait.

## 1. Bugs critiques constatés en ligne

1. **Titre d'accueil coupé.** Entre ~700 et ~1100 px de largeur (petits
   portables, tablettes paysage, fenêtres non maximisées), la carte « console »
   du hero passe par-dessus le titre : on lit « Relier ce qui exist… / Faire
   agir l'ensem… ». La première phrase du site est illisible.
   Capture : `docs/audit/accueil-titre-coupe-800px.jpg`.
2. **Sections noires au défilement.** En défilant à la molette, les sections
   « manifesto » et « preuve » de l'accueil restent entièrement noires sur
   plusieurs écrans complets — le visiteur croit que la page est vide. Le
   contenu existe mais les effets de scroll de `site-v4.js` ne le peignent pas
   de façon fiable. Capture : `docs/audit/accueil-section-noire-scroll.jpg`.
3. **Artéfacts sur les légendes (mobile).** Des pastilles « signal » se
   superposent au texte des légendes de figure (ex. « L'intelligence demeure
   près du lieu ») et donnent l'impression d'un texte barré de noir.
4. **Compteur de visiteurs cassé.** `counterapi.com` bloque les requêtes
   (erreur CORS dans la console sur chaque page). Le pied de page affiche
   « Visiteurs — » en permanence.
5. **Collisions texte/image sur les pages intérieures.** Les titres débordent
   sur les zones claires des photos (« Un seul point d'entrée. » touche le bord
   droit; le titre du laboratoire se lit mal sur l'ambulance jaune). Le voile
   d'assombrissement est insuffisant et non systématique.

## 2. Dette structurelle du dépôt

- **4 systèmes CSS empilés** : `styles.css` (2250 lignes, v1), `site.css`
  (2271 lignes), `site-v3.css` + `site-v4.css` + `site-signature.css`
  (3 couches chargées en même temps, la dernière écrasant les deux autres).
- **5 fichiers JavaScript** dont deux chargés partout (`site-v3.js`, 1659
  lignes + `site-v4.js`) et trois orphelins (`script.js`, `site.js`,
  `static-runtime.js`).
- **Code mort confirmé** (référencé par aucune page) : `battery-live.css`,
  `static-runtime.js`, `data/battery-status.json`, `concept-home/`,
  `ui-system-preview/`, `og-jarvis-twin.png`, `og-trading-lab.png`,
  `data/site-data.js` et `tools/build-site.mjs` (le générateur ne correspond
  plus aux pages en ligne).
- **12 articles Markdown** (`articles/*.md`) jamais rendus en HTML — du bon
  contenu invisible.
- **1,7 Mo de build React haché** à la racine de `assets/` (quatorze fichiers
  `framework-*.js`, `index-*.js`…) qui ne servent qu'à la carte d'anniversaire
  `/sudo-bonne-fete/` (QR, août 2026).
- **Doublons de pages** : `about.html`, `about/`, `a-propos/` ; `contact.html`
  et `contact/` ; sept anciennes pages devenues redirections.
- La police sérif du design est **Georgia** (police système) — l'élégance
  voulue par le système visuel n'est pas réellement au rendez-vous.

## 3. SEO, performance, accessibilité

- Bon : canoniques, Open Graph, sitemap, robots.txt, domaine propre, balises
  descriptives, `lang="fr-CA"`, lien d'évitement, structure Hn globalement
  saine.
- À corriger : le sitemap référence l'ancienne arborescence; deux CSS et deux
  JS bloquants sont chargés sur chaque page; les reveals JS masquent le
  contenu si le script échoue (aucune garantie sans JS); contrastes irréguliers
  sur photos; `aria-selected` sur des boutons sans rôle d'onglet complet.

## 4. Ce qui est bon et conservé

- Tous les **textes** (promesse, six capacités, plateforme, laboratoire,
  vision, confiance, recherche) — réutilisés tels quels ou resserrés.
- Toutes les **images** de `media/` (hero architecture, command center, hub,
  solutions, ambulance, Terre de nuit) — elles sont excellentes.
- Les trois **documents de référence** de `docs/` — la refonte les applique
  enfin fidèlement (navigation, rôles de pages, palette nuit/or, états).
- Les **intégrations** batterie (`integrations/`) et la configuration publique.
- La carte d'anniversaire `/sudo-bonne-fete/` et son build (QR déjà imprimé).
- `CNAME`, `.nojekyll`, redirections des anciennes URL.

## 5. Décisions prises pendant la refonte

| Sujet | Décision |
| --- | --- |
| Génération | Nouveau générateur minimal `tools/build.mjs` (Node sans dépendance) : contenu dans `src/`, HTML produit à la racine pour GitHub Pages |
| CSS/JS | Un seul `assets/css/site.css` + un seul `assets/js/site.js` |
| Polices | Geist + Geist Mono conservées (locales) ; ajout de **Fraunces** auto-hébergée pour les titres sérif |
| Reveals | Sans JavaScript, tout le contenu reste visible (le masquage n'est appliqué que si JS est présent) |
| Compteur visiteurs | Retiré (service cassé) |
| Articles | Préservés dans `src/articles/` — publier une section « Journal » est une décision à prendre (voir §6) |
| Anciens CSS/JS, pages mortes | Supprimés (l'historique git garde tout) |
| Build React `/assets/*.js` | Conservé tel quel pour `/sudo-bonne-fete/` (chemins absolus fragiles), documenté dans le README |
